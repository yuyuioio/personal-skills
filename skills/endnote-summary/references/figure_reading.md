# 正文全部图表与重要 SI 图表：配原图的证据解读

## 覆盖范围

标准总结先逐页盘点 **正文所有 Figure、Table、Scheme 和未编号但承担说明作用的图片**；含结构式、流程、示意、模型、照片及所有 a/b/c 子图。按原文顺序解释，不能把“全部图”缩成四五张关键图，也不能仅解释多面板中的部分。全文只有 HTML 时使用真实页面内原图/表格并记录来源，不能假造 PDF 页码；没有表格时如实说明。

SI 先浏览全部可读内容，再选择会影响文章理解或复现的图表：支持主要结论的证据、结构鉴定、制备/优化、控制/阴性结果、统计/重复、认证、拟合或计算细节，以及与主文不一致或限定结论的结果。无需把大量同类谱图无差别逐峰分析，但解释所选图的范围和理由要明确。被省略的 SI 图表按图号列出理由；相同理由可成组列出，但不要用“其余略”代替清单。正文全部表格同样截图和解释，不能只靠正文数据汇总替代。

用户明确要求快读、某几张图或缩小范围时服从该范围；资料受阻或无法辨认时逐项报告缺失，不能标为全覆盖完成。下载、阅读、入选、裁剪、解释是独立状态。

建议每篇保留 `figure-plan.json` 清单，至少包含：来源文件/哈希、正文或 SI、物理页码、图表号、全部面板、是否选取、SI 选取/未选理由、裁剪区域、资源路径和实际解释状态。页码、图号和面板由阅读者根据原页核定，不把程序搜索命中当作完整图表清单。

以下要点按共享坐标和方法合并表达；每个面板有对应结果即可，不为套齐重复小标题扩写。

## 每一图表必须解释什么

1. **图题/表题与图注：** 给出中文翻译或忠实释义，解释理解数据必需的条件、缩写、图注及表脚。原题过长可准确概括，不能只贴英文题目。
2. **要解决的问题：** 本图是实验、模拟还是示意，它检验论文哪项具体主张；结构/流程图可能仅说明设计，不能强称“实验验证”。
3. **坐标与全部信息编码：** 逐面板说明横纵轴名称、变量含义、单位、范围、线性/对数、断轴、双轴和归一化；说明线/点/符号/颜色对应什么，图内缩写、箭头、拟合式、标注数值、误差棒、星号、阴影、色标、比例尺、插图等。若多个面板共享标注，集中定义后说明适用范围；没有坐标的示意/结构图解释对象、位置、键/层/箭头的含义。无法辨认的文字标为未辨认，放大后仍不清楚则保留限制，不猜。
4. **逐子图数据：** 每个 a/b/c 面板分别写样品/条件、对照、实际趋势或数值、测得量与拟合/换算量。概念相同的面板可共用方法说明，但结果不能合并到无法识别各面板。
5. **支持了哪些结论：** 对应论文中的具体结果、创新或机制步骤；同时指明观测、作者解释与自己的推断。
6. **为什么该测试能检验：** 写清“激励/探测原理 → 信号怎样响应目标性质 → 如何由信号提取物理量 → 在哪些前提下支持所述结论”。需要其他图联合判断时交叉定位；列出关键假设和替代解释。避免只说“表明性能提高”“验证机制正确”。
7. **表格专属信息：** 各行列的对象、条件和单位，± 的定义、括号、粗体/下划线/星号、缺失符号、统计 n 与独立单位、脚注、最优值与平均值、可比性和实际差异。未定义误差不能默认 SD；不把空值当零。

方法的系统原理仍在总结最后的“所有表征与测试方法的原理解析”汇总；图旁保留足够原理连接，不能只写“原理见文末”而跳过本图为什么支持结论。

## 从核验 PDF 裁剪原图/原表

优先页面渲染后裁剪，保证矢量线条、标签、表格文字和图注一起保留；直接提取 PDF 内嵌位图往往丢失坐标或只拿到一个面板。不得生成、重绘或修饰曲线冒充原文截图。裁剪属于原页选区，不改变数据、色标或对照。

- 先看整页确定区域，一次批量以约 180–240 dpi 渲染，选区宁宽勿窄。首次核对图号、面板对应与关键内容可读性；正确且可读后停止，不因版式、留白、边缘文字或更高 DPI 而重截。
- 保留正在解释的面板及其关键坐标、图例、数据与必要色标/比例尺。图题图注/表题表脚能顺带截入即可；图注截断或未截入时读源页并在文字中概括，不为补齐图注重新截图，不声称截断部分是完整图注。
- 同一图只嵌入一次，后续交叉引用；可读的整页截图同样合格。仅当关键内容确实不可读时局部补截一次；仍不可读则说明限制，不循环放大或重渲染。
- 自动边界不可靠时直接保留宽松选区或整页，并说明目标图位置；允许邻近文字/图像，只需明确目标编号且不混淆来源，不为去除邻图反复裁边。
- 用 `figures/main_fig01.png`、`figures/si1_figS22.png` 等包内相对路径，就地插入首次实质解释处；原表也插图，必要时额外转写 Markdown 表供比较。
- 图旁列源文件、物理页码、图表/公式号；实际查看每张成图一次。只有错图、遗漏所讲面板或关键数据、遮挡/模糊影响理解才局部补截；外观和非必要图注不修正。不要把截图成功或哈希一致说成“内容解读正确”。

### 公式截图

公式可直接用源页截图表示，无需手写、OCR 转写或重新排版。图已含所需公式时复用现图；否则宽松截入公式及必要符号定义，保存为 `figures/main_eq01.png` 等，标来源物理页码/公式号。正文只解释关键变量、单位、物理意义和适用条件。裁剪计划使用已有 `kind: image`，`number` 如 `Eq. 3`；无需修改脚本或另造公式绘图流程。原文疑似错误保留原貌并简注，只有用户要求推导/核验时进一步检查。

### 本包裁剪命令

`scripts/figure_assets.py` 使用本地 pypdfium2 + Pillow，不上传 PDF、不调用生成式绘图。先调用当前环境的依赖定位工具或使用已有解释器，缺包时再按需安装；它不会自动下载依赖或创建图表解释。

示例计划（路径相对于计划文件所在目录；下面是假数据，必须替换为本篇真实清单和 SHA-256）：

```json
{
  "sources": {
    "main": {"path": "article.pdf", "sha256": "填入正文PDF的64位SHA256"},
    "si1": {"path": "supporting-information.pdf", "sha256": "填入SI的64位SHA256"}
  },
  "items": [
    {"id": "main_fig01", "source": "main", "kind": "figure", "number": "1", "page": 2,
     "panels": ["a", "b", "c"], "selected": true, "bbox": [0.04, 0.08, 0.96, 0.57]},
    {"id": "main_table01", "source": "main", "kind": "table", "number": "1", "page": 4,
     "selected": true, "bbox": [0.05, 0.72, 0.95, 0.95]},
    {"id": "si1_figS22", "source": "si1", "kind": "figure", "number": "S22", "page": 28,
     "panels": ["a", "b", "c"], "selected": true,
     "selection_reason": "检验主要结论中的薄膜有序性", "bbox": [0.05, 0.08, 0.95, 0.55]},
    {"id": "si1_figS01", "source": "si1", "kind": "figure", "number": "S1", "page": 8,
     "selected": false, "selection_reason": "中间体谱图已读；结构鉴定重点解释终产物谱图，未逐峰分析本图"}
  ]
}
```

`bbox` 为**按页面正常显示方向、以左上角为原点**的 `[left, top, right, bottom]`，四数均为 0–1；旋转页也按实际渲染显示方向选区。页码从 1 开始；选框不能凭其他文章的示例复用。跨页图拆成两个有独立 id 的条目，写清面板/图注关联。

```bash
python scripts/figure_assets.py render --plan paper-folder/figure-plan.json --paper-dir paper-folder --dpi 200
python scripts/figure_assets.py check --manifest paper-folder/figure-assets.json --markdown paper-folder/Actual-title__10.xxxx_suffix.md
```

`render` 核验源哈希、页码、选框与输出路径，输出 PNG 和 `figure-assets.json`，默认不覆盖已有资源；有意重新裁剪时加 `--overwrite`。按实际返回路径写 Markdown。计划中的正文项必须入选，SI 每项需选取/未选理由；工具不会自动发现遗漏的图表或编写图解。

`check` 核查选定图片均在最终 Markdown 使用、资源未改变、链接可在包内解析及来源未变，并标出未入选 SI。它是结构检查，**不证明清单已覆盖全部原文、不证明文字解释/面板解读/裁剪可读性正确**；这些必须另与原页和成品逐一核对。不支持的复杂 Markdown 引用式图片请改用简单内联相对图片链接。

`render` 初始将 `visual_review`、`interpretation_review` 标为 `pending`。首次实际看图并确认图号/关键内容可读后即记 `visual_review: checked`，核对解释后再记 `interpretation_review: checked`，避免成品阶段重复查看。`check` 的 pending 是检查记录提示，不是要求重新裁剪；已有实际检查但漏记时补记录。结构通过与状态标记都不取代实际阅读；无新增错误则不重复全量检查。

## 最终交付检查

- 正文 Figure/Table/Scheme 清单对照原页全部覆盖；每个面板都有解释，没有只讲题目或只讲一部分。
- 已选 SI 每项有理由、原图及同等解释；未选项有图表号及理由；缺失资料与未选资料分开。
- 图题表题、坐标、图内标注、观察、结论映射及“原理为何支撑推论”齐全；无法确定的文字/单位/误差明确标注。
- 最终 `.md` 就地显示对应截图，每张实际查看过；原图/原表与正文/SI/页码、图号和哈希绑定。
- 主 Markdown 与 `figures/` 必须一起保留和移动；相对链接让文章文件夹可搬移，但 Markdown 本身不储存这些图片的字节。EndNote 仅复制 `.md` 不保证会收进资源目录，不声称单个附件可保留全部图片；当前默认按 [zotero_sync.md](zotero_sync.md) 将主 MD、其引用的图片资源和内嵌原图 HTML 保存到 Zotero 同一主条目下，并分别核验两份附件；仅明确要求 EndNote 时沿用手动附件模式。
